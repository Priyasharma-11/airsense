# Testing Strategy

| Layer | Tool | Location | Count | What it proves |
|---|---|---|---|---|
| ML unit | pytest | `backend/tests/test_ml_pipeline.py` | 17 | Bounds removal, flat-line detection, the hourly slot rule, short-gap-only interpolation, **no future leakage**, target masking, target-calendar shift, metrics, AQI breakpoints, interval coverage, inference contract on the real model |
| Database | pytest | `backend/tests/test_database.py` | 5 | Alembic upgrade → downgrade → upgrade round-trip, CHECK / FK / UNIQUE constraints, idempotent upserts, UTC preservation, catalog load |
| API integration | pytest + TestClient | `backend/tests/test_api.py` | 23 | Health and readiness, error envelope and security headers, register/login (cookie + bearer), duplicate and invalid input → 409/422, tampered token → 401, OAuth2 token flow, password reset (single use, no enumeration), preferences validation, stations/search, current, history and range validation, pagination, all analytics, GeoJSON/hotspots/nearest, **forecast generated by the model and cached**, 422 for stations without data, model metrics (XGBoost < persistence at +24 h), admin-only endpoints → 403, alert CRUD + evaluation + de-duplication + **cross-user isolation**, account deletion, rate limiting → 429 |
| Frontend unit/component | Vitest + React Testing Library | `frontend/src/**/*.test.ts(x)` | 22 | AQI/format helpers (IST), API client error parsing, network failure → ApiError (never fake data), query serialisation, ErrorState/AqiBadge/Segmented/AqiGauge accessibility, login validation and server errors |
| End-to-end | Playwright (Edge locally, Chromium in CI) | `frontend/e2e/` | 7 | Landing shows live data and a model forecast; protected-route redirect; invalid login; **register → dashboard → forecast (station switch) → analytics filter → map (10 markers) → alert rule → evaluate → delete with confirm → settings persist → logout**; password reset; injected API failure shows an error; mobile layout has no overflow and the drawer navigation works |

Total: **45 backend + 22 frontend + 7 E2E**, all passing on 23 Nov 2026 (Windows 11, Python 3.13, Node 24).

## Running
```bash
cd backend && pytest                                   # SQLite
AIRSENSE_TEST_DATABASE_URL=postgresql+psycopg://... pytest   # PostGIS (runs real migrations)
cd frontend && npm test && npm run typecheck && npx eslint src e2e
cd frontend && npx playwright test                     # requires API :8000 and web :3000
```

## Principles
* Tests use the **real processed dataset and the real trained model**, not mocks of the ML layer.
* Time series is never split randomly. Leakage is tested directly.
* E2E creates unique users per run. The auth rate limit is relaxed only in the E2E environment, and 429 behaviour is covered by a backend test.

## Manual QA performed
Every page was visually inspected in the in-app browser at 1024 px and in dark theme. Issues found and fixed during QA:
the cramped dashboard top row, an analytics filter layout bug, CardHeader overflow, CARTO tiles that now need an API key (switched to OSM), duplicate time-axis labels,
cold-start latency under concurrent requests (single-flight cache + warm-up), and Next 16 Cache Components validation errors (disabled, with the reason documented).
